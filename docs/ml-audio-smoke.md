# Проверка ML на двух исходных MP3

Локальный прогон выполнен на `ml/data/private/meeting_01.mp3` и `meeting_02.mp3`. Их SHA-256 совпадают с файлами «Совещание №1.mp3» и «Совещание №2.mp3», предоставленными командой. Файлы с записью и полными расшифровками находятся в каталогах, исключённых из Git.

## Что обучалось раньше

Команда `python ml.py train` обучает только вспомогательный детектор реплик с поручениями: TF-IDF по символам и логистическая регрессия на 498 синтетических примерах. 81 пример используется для выбора порога, 78 — для теста. Обучение занимает секунды; MP3, ASR, определение говорящих и извлечение итоговых карточек в нём не участвуют. Test F1 0,844 измерен на синтетическом тексте и не является оценкой качества протокола на настоящем совещании.

## Фактический аудиопрогон

В отдельное локальное Python-окружение установлены `faster-whisper==1.2.1` и `huggingface-hub==0.36.0`. Модель `Systran/faster-whisper-small` скачана в `ml/models/asr/small`; зафиксированная ревизия — `536b0662742c02347bc0e980a01041f333bce120`. Распознавание выполнялось на CPU с `local_files_only=True`; аудио не загружалось во внешние сервисы.

```powershell
cd ml
.\.venv-audio\Scripts\python.exe ml.py transcribe --audio data/private/meeting_01.mp3 --out outputs/private_meeting_01/asr.json --model-path models/asr/small --device cpu
.\.venv-audio\Scripts\python.exe ml.py transcribe --audio data/private/meeting_02.mp3 --out outputs/private_meeting_02/asr.json --model-path models/asr/small --device cpu
.\.venv-audio\Scripts\python.exe ml.py rank --transcript outputs/private_meeting_01/asr.json --out outputs/private_meeting_01/candidates.json
.\.venv-audio\Scripts\python.exe ml.py rank --transcript outputs/private_meeting_02/asr.json --out outputs/private_meeting_02/candidates.json
```

| Запись | Длительность | Реплик ASR | Отмечено детектором | Расхождение слов с DOCX |
|---|---:|---:|---:|---:|
| №1 | 274,25 с | 66 | 63 | 31,3% |
| №2 | 206,03 с | 56 | 55 | 12,5% |

Расхождение посчитано командой `ml.py wer` с `data/private/meeting_0N.transcript.json` как reference. Это **не подтверждённый WER**: DOCX мог быть сокращён или отредактирован, а для настоящего WER нужна дословная ручная разметка аудио. В первом ASR встречаются ошибки в именах и географических названиях. ASR выдаёт текст и временные метки, но пока помечает говорящего как `UNKNOWN`.

Детектор с порогом 0,2 почти все аудиореплики считает кандидатами. Он не годится как надёжный фильтр настоящего совещания без разметки и дополнительной оценки. Его выход — оценки реплик, а не готовые поручения. Записи не использовались для дообучения ASR или классификатора.

## Следующий этап для протокола из MP3

Для диаризации ещё нужны установленный `pyannote.audio` и локальные веса Community-1, доступ к которым ограничен владельцем модели. Для извлечения задач нужна локальная Ollama с указанной в ML-коде моделью Qwen. Их нет в текущем окружении, поэтому `ml.py run` и backend AI worker с реальным результатом не проверены. Полученные ASR JSON можно использовать как промежуточный вход; нельзя подменять ими подтверждённые имена говорящих или карточки поручений.
