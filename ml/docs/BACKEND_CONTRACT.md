# Контракт ML для backend

Вход: локальный путь к записи. Опционально подтверждённая ISO-дата совещания, число говорящих и проверенная карта `speaker_id -> имя`. Пользовательский upload должен сохраняться backend в отдельную папку с проверкой формата и размера; shell-команду нельзя собирать конкатенацией пользовательских строк.

Запускайте CLI через массив аргументов процесса. Пример Python:

```python
subprocess.run([audio_python, 'ml.py', 'run', '--audio', saved_file,
                '--out', job_directory, '--device', 'cpu'], check=True)
```

Для веб-приложения процесс должен идти в очереди jobs, не в HTTP request worker. Серверный API, аутентификация и очередь в этот ML-комплект не входят.

Готовый адаптер без HTTP-сервера: `integration_example.py`, функция `process_meeting(...)`. Она использует новый каталог задания, передаёт аргументы без shell и возвращает словарь результата. Ошибки процесса передаются вызывающему коду через `subprocess.CalledProcessError`; backend должен пометить job как failed и предложить повторить конкретный этап. Для массовой обработки ограничьте очередь одним GPU-заданием одновременно на ноутбуке с 6 ГБ VRAM.

Выход `result.json`:

| Поле | Значение |
|---|---|
| schema_version | 1 |
| meeting_id / meeting_date | ID / подтверждённая дата или null |
| segments | реплики с id, text, speaker, speaker_name, start, end |
| summary | пункты text + segment_ids |
| tasks[].task | краткое описание результата |
| tasks[].owner | участник/подразделение или null |
| tasks[].owner_basis | explicit / speaker_map / unknown |
| tasks[].owner_speaker_ids | подтверждённые соответствия голосам; может быть [] |
| tasks[].deadline_text | исходная формулировка срока или null |
| tasks[].due_date | ISO-дата или null |
| tasks[].date_status | способ/причина нормализации; см. dates.py |
| tasks[].evidence | segment_id, дословная quote, start/end, speaker |
| tasks[].needs_review | всегда true на выходе модели |
| tasks[].status | draft |

`start/end` измеряются в секундах исходной записи. Для DOCX они `null`. Поле `speaker` — источник высказывания, **не автоматически исполнитель**. Модель может назвать человека из текста, которого нет в списке голосов.

JSON Schema сырого ответа LLM лежит в `meeting_ml/extract.py` как `SCHEMA`. Backend должен хранить исходный результат модели отдельно от исправлений секретаря и истории согласования. Напоминания включайте только по подтверждённым заданиям с определённой датой.

Ошибка цитаты или схемы завершает команду ненулевым кодом; `.raw.json` сохраняется рядом для локального разбора. Не выдавайте такой файл пользователю как готовый протокол. `run` также сохраняет промежуточные ASR/diarization/transcript; после исправления настройки повторяйте только необходимый этап.

Код проверяет существование цитат, а не смысловую истинность поручения. Интерфейс должен позволять отвергнуть задачу, исправить ответственного, выбрать итоговый срок и прослушать контекст.
