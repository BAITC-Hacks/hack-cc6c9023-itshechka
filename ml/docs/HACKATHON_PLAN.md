# Что лучше сделать для хакатона

Главная демонстрация: **«Из записи в подтверждённые поручения с доказательствами»**. Секретарь нажимает на поручение, слышит нужный фрагмент, исправляет имя/срок и подтверждает протокол. Это напрямую решает проблему потерянных поручений и даёт понятное отличие от простого суммаризатора.

В описании кейса 25 баллов отведены работоспособности, 25 — технической реализации и 25 — README/воспроизводимости. Значит, работающий локальный сценарий с понятными ограничениями и ZIP важнее необязательной интеграции с СЭД или обучения большой модели с нуля.

## Обязательная ML-цепочка

| Требование кейса | Выбранная реализация | Что показать жюри |
|---|---|---|
| Русская/казахская/смешанная речь | multilingual Whisper, тест на собственных записях | три коротких реальных прогона |
| Различение говорящих | Community-1, временная привязка на уровне слов | разноцветные реплики и подтверждение имён |
| Ответственный, задача, срок | локальная Qwen + JSON-схема + проверка цитат | явное поручение и косвенное поручение |
| Саммари | пункты со ссылками на реплики | краткая сводка без вымышленных цифр |
| Экспорт | результат ML -> экспорт приложения | PDF через имеющийся HTML или реализованный командой DOCX |
| Закрытый контур | локальные веса и inference, никаких облачных API | отключить интернет после скачивания и повторить |

## Сложные случаи из реальных образцов

- Совещание 1: 10 поручений. Аудит сначала обсуждают на две недели, затем согласуют три недели и 15 октября. Итоговая реплика повторяет уже выданные поручения.
- Совещание 2: 6 строк в авторской таблице. Претензию поручают юристу Ерлану, хотя докладывает другой участник. Справка имеет событийный срок «после совещания», а уведомление и шаблон договора не имеют срока.
- Дату записи нельзя восстановить из дня копирования файлов. Нельзя подставлять текущий год без установленной даты совещания.
- Авторские таблицы являются ориентиром; организация обучения и недельная смета объединены, хотя в разговоре закрыть очередь предлагают за месяц. Храните отдельные результаты/сроки в UI или явно документируйте правило группировки.

## Порядок работы команды

1. **Сначала воспроизводимость.** Другой участник распаковывает ZIP и выполняет quickstart. ML-разработчик запускает ASR, диаризацию и LLM по отдельности, сохраняет результаты с provenance.
2. **Проверка русских образцов.** По двум протоколам анализируется извлечение на чистом тексте, затем на ASR. Не путать улучшение промпта на этих примерах с независимым тестом.
3. **Недостающие языки.** Записать вымышленные встречи на казахском и смешанном языке, проверить носителем. Сделать ручную расшифровку и небольшую временную разметку говорящих.
4. **Frontend/backend.** Загрузка файла, отображение стадий, транскрипт, проигрывание цитат, редактор исполнителя/срока, подтверждение и экспорт. Не показывать внутренние метрики модели как уверенность в правильности задачи.
5. **Финальная проверка.** Новый разговор, которого не было в настройке; выключенный интернет; другой ноутбук; отсутствие случайно вложенных токенов и непроверенных имён.

## Что обучать

В этом комплекте обучен компактный детектор реплик с поручениями. Он дешёвый, понятный и переносимый, но синтетический тест показывает скромное преимущество над простым baseline. Не выдавайте его за основной интеллект системы.

ASR и LLM для первой версии используйте готовые. Две записи суммарно около восьми минут — хорошая функциональная проверка, но слабый материал для дообучения ASR и оценки обобщения. Это также не размеченный датасет диаризации.

Если останется время, вручную разметьте дополнительные реальные/смоделированные **независимые** диалоги. Сначала улучшайте инструкции извлечения и словарь имён. LoRA обсуждать после появления достаточно разнообразных проверенных пар «диалог -> JSON с evidence» и отдельного теста. Массовая генерация шаблонов не заменяет разнообразия реальных разговоров.

## Чего не обещать на защите

- 84% качества протокола по F1 вспомогательного синтетического классификатора.
- Распознавание личности по голосу: диаризация определяет группы похожих голосов, имя подтверждает человек.
- Проверенный казахский ASR только на основании поддержки языка моделью.
- Полностью автономную установку из маленького ZIP без весов, Python и системных библиотек.
- Временные метки, полученные из текстового DOCX: они в таком входе отсутствуют.

Для публичного демо используйте вымышленные записи. Подмена имён в тексте не анонимизирует голос и произнесённые имена в исходном MP3.
